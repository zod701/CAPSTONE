## 병합 완료

- 경계: 보유한 `ver20260701` 원본에서 인천 11군구를 대상 지역으로 전환. 웹 경계 56 → 67개.
- 버스 정류소: 50,019 → 56,530개. 인천 소재 6,479개. 전국 원본의 ICB 6,872건을 좌표로 선별하고 기존 GGB·SEB 등록과 병합했다. 다른 승강장은 분리한다. 원본 ICB 기준일은 2025-10-31이며 최신 인천 정류소 원본으로 추가 갱신이 필요하다.

- 보유 GTFS에서 인천1·2호선 배차를 생성했다. 2025년 3월 원본에 없는 검단 연장 3개 역과 자기부상철도 6개 역은 배차 정보가 없으며 기존 기본 대기 추정을 사용한다.

## API 재확인

기존 `DATA_GO_KR_API_KEY`로 공식 HTTPS 주소를 각각 1회 조회했을 때 두 서비스 모두 `403 / SERVICE_KEY_IS_NOT_REGISTERED_ERROR(30)`였다. 사용자 활용신청 후 HTTPS로 두 차례 재확인한 결과 HTTP 상태는 200이지만 본문은 모두 `HTTP_ERROR(04)`였다. 정상 데이터는 아직 수신하지 못했다. 신청 반영 지연인지 제공기관 연계 장애인지는 이 응답만으로 확정할 수 없다.

키와 요청 URL은 기록하지 않았다.

### 이번 연동 및 재확인

- 기존 `DATA_GO_KR_API_KEY`를 기존 경기 호출과 동일하게 디코딩해 `serviceKey`로 전달한다. 인천 공식 활용가이드의 XML 스키마를 사용한다.
- `realtime.py`에 인천 도착·노선정보 조회를 추가했다. `ICB` 원천 ID로 호출하며, 노선 번호는 로컬 순서표 우선·`getBusRouteId` 보완이다. 도착정보 15초, 정적 노선명·유형 24시간 메모리 캐시를 사용한다.
- 도착·노선 서비스별 쿼터, 인증 실패, 외부 장애, XML 해석 실패를 구분한다. 오류를 빈 도착정보로 처리하지 않는다. 동일 노선은 서울→경기→인천 순으로 유효 예측을 선택한다.
- `fetch_incheon_routes.py`와 `build_bus_route_seq.py --incheon`으로 수집·병합 경로를 추가했다. 전체 노선 수집에 성공한 파일만 자동 병합하며, 실패 시 현재 DB를 변경하지 않는다. ICB ID에 연결되지 않는 정류소는 별도 보고하고 제외한다.
- 공식 도착·경유 정류소 API를 HTTPS/HTTP 및 `ServiceKey`/`serviceKey`로 비교했지만 모두 HTTP 200 안에 `HTTP_ERROR(04)`를 반환했다. 새 수집기의 `getBusRouteNo` 요청도 동일하다. 권한 반영 지연과 제공기관 장애 중 어느 것인지는 확정할 수 없다.
- 따라서 **연동 코드는 추가됐지만, 실제 정상 응답 검증·인천 자체 노선 DB 수집은 미완료**다. 외부 API 복구 후 수집 명령을 다시 실행하고 빈 `routeNo`의 전체 노선 목록 제공 여부도 확인해야 한다. 인천 배차·요금 검증 범위는 기존과 같다.
