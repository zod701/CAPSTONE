# 택시 최대 1회 파레토 경로 탐색

`algo.pareto_search`는 작은 정적 교통망에서 정확한 비교 기준을 만드는 연구용 모듈이다.
서비스의 후보 생성(`algo/search.py`)이나 공개 API 를 호출하지 않는다. 서비스는 같은 꼴을 후보 규칙으로 쓴다(method.md §3.8).
입력된 교통망에서 시간과 요금의 파레토 비용쌍을 구하고, 각 비용쌍의 대표 경로 하나를 반환한다.

## 하나의 경로 표현

택시를 한 번 타는 경로는 다음처럼 분해할 수 있다.

```text
O --대중교통·도보*--> u --택시 1회--> v --대중교통·도보*--> D
```

`*`는 연결을 0회 이상 사용할 수 있다는 뜻이다. 앞뒤 구간은 여러 환승을 포함하거나 비어 있을 수 있다.
택시를 전혀 사용하지 않는 경로도 함께 탐색한다.

| 기존 유형 | 통합 모델에서의 표현 |
| --- | --- |
| A: 첫 구간 택시 | `u = O` |
| B: 끝 구간 택시 | `v = D` |
| C: 우회 중 재탐색 | 중간 `u`에서 택시로 새 `v` 또는 `D`에 연결 |
| D: 긴 대기·환승 대체 | 중간 `u, v` 사이를 택시로 연결 |

모든 허용 연결이 입력되면, 기존 경로 밖의 두 노선 연결이나 여러 환승을 건너뛰는 경로도 탐색 대상이다.
우회율, 대기시간, 최소 절약시간, 거리 반경, 상위 후보 수로 연결을 제외하지 않는다.
이 모듈이 지도에서 연결을 수집하거나 모든 택시 앵커 쌍을 자동 생성하는 것은 아니다.

## 입력과 출력

```python
from algo.pareto_search import Edge, pareto_journeys

edges = [
    Edge("O", "U", "walk", 120),
    Edge("U", "D", "transit", 1380, 1500),
    Edge("O", "V", "taxi", 480, 4800),
    Edge("V", "D", "transit", 120, 1500),
    Edge("O", "D", "taxi", 720, 7000),
]
journeys = pareto_journeys(edges, "O", "D")
assert [(j.time_s, j.fare) for j in journeys] == [(600, 6300), (1500, 1500)]
for journey in journeys:
    print(journey.time_s, journey.fare, [edge.mode for edge in journey.edges])
```

저장소 루트에서 Python으로 실행한다. 외부 API나 별도 패키지 설치가 필요하지 않다.

- `Edge(start, end, mode, time_s, fare=0)`는 방향이 있는 연결이다. 역방향도 가능하면 따로 입력한다.
- 지점 ID는 문자열이며, `mode`는 `walk`, `transit`, `taxi` 중 하나다.
- `time_s`는 초, `fare`는 모든 연결에서 동일한 통화 단위이며, 둘 다 유한한 비음수여야 한다. 잘못된 mode·비용이나 누적 합계의 무한대 오버플로는 `ValueError`다.
- 비용은 고정되고 가산적이다. `transit`의 요금은 해당 연결에서 추가되는 금액이다.
- 택시 연결 하나가 승차부터 하차까지 한 번의 전체 택시 이용이다. 도로 구간별로 나누면 여러 번의 택시 이용으로 해석된다.
- 호출·접근·대기·연결에 필요한 시간과 요금은 입력자가 해당 연결 비용에 반영한다. 기본 대기시간이나 실시간 운임은 적용하지 않는다.
- `pareto_journeys(edges, origin, destination)`는 `Journey` 목록을 시간, 요금 순으로 정렬해 반환한다.
- `Journey.time_s`, `Journey.fare`는 합계이고 `Journey.edges`는 이동 순서대로 된 `Edge` 튜플이다.
- 같은 상태·비용에서는 먼저 발견한 라벨을 남긴다. 같은 입력 순서의 결과는 결정적이며, 목적지에서 택시 0회·1회의 비용까지 같으면 0회 경로를 남긴다. 모든 경로 모양을 열거하는 API는 아니다.
- 도달할 수 없으면 빈 목록이며, 출발지와 목적지가 같으면 비용 `(0, 0)`의 빈 경로를 반환한다.

## 공통 탐색 조건과 정확성

탐색 상태는 `(지점, 택시 사용 여부)`다. 도보·대중교통은 사용 여부를 유지하고,
택시는 `미사용 → 사용`으로만 이동한다. 사용 상태에서는 다른 택시 연결로 이동할 수 없다.

각 상태에는 `(누적 시간, 누적 요금)` 라벨을 여러 개 둔다.
기존 라벨이 새 라벨보다 두 비용 모두 작거나 같으면 새 라벨은 필요 없다.
반대로 새 라벨이 기존 라벨을 지배하면 기존 라벨을 제거한다.
빠르고 비싼 라벨과 느리고 저렴한 라벨은 모두 유지한다.
동일 비용 중복도 제거하므로 비용 0인 순환을 계속 확장하지 않는다.
더 확장할 라벨이 없어지면 목적지의 미사용·사용 결과를 합쳐 다시 파레토 집합을 구한다.

중간 지점에서 택시 사용 여부가 다른 라벨끼리는 비교하지 않는다.
지금까지의 비용이 같아도 이후에 택시를 탈 수 있는지가 다르기 때문이다.
목적지에서는 후속 이동이 없으므로 두 상태의 최종 비용을 함께 비교할 수 있다.

정확성은 다음 조건에서 성립한다.

1. 유한한 그래프에 가능한 연결이 모두 들어 있고, 각 연결의 시간·요금이 고정된 비음수다.
2. 같은 상태에서는 이후 가능한 이동과 추가 비용이 같다. 따라서 지배되는 접두 경로를 바꾸어도 후속 경로가 불리해지지 않는다.
3. 택시 1회 경로는 위 세 부분으로 분해되며, 상태 전이가 정확히 그 제약을 표현한다.
4. 확장된 상태 그래프에서 순환을 제거해도 비용이 증가하지 않는다. 양의 비용 순환은 지배되고, 0비용 순환은 중복 제거된다. 따라서 최종 비용쌍은 유한한 단순 상태 경로들로 대표할 수 있다.

보장 대상은 **입력 그래프와 입력 비용에서의 파레토 비용쌍**이다.
누락된 교통 연결, 추정 비용 오차, 임의로 제외한 앵커에 대한 실제 교통망 전체의 최적성은 보장하지 않는다.
부동소수점 비용은 Python의 덧셈과 비교 결과를 사용하므로, 실험에서는 정수 초·정수 원을 쓰면 비교가 명확하다.

시간가치(VOT)는 탐색이 끝난 뒤 추천 경로를 고르는 데 적용한다.
시간과 요금의 가중합 하나로 탐색하면 모든 파레토 해를 얻을 수 없다.
예를 들어 `(10분, 5,000원)`, `(20분, 4,500원)`, `(30분, 1,000원)`은 모두 비지배적이지만,
가운데 경로는 어떤 비음수 시간가치의 선형 가중합에서도 최선이 되지 않는다.

## 시간표·환승요금 확장 경계

실제 도착시각, 탑승 차량, 환승할인 이력에 따라 후속 선택이 달라지면 지점과 택시 여부만으로는 부족하다.
예를 들어 같은 정류장에 도착한 두 라벨을 비교해 보자.

| 라벨 | 도착 시점 | 지불 요금 | 환승할인 만료 | 20분 시점 출발편의 추가 요금 | 최종 요금 |
| --- | --- | --- | --- | --- | --- |
| P | 10분 | 1,000원 | 12분 | 2,000원 | 3,000원 |
| Q | 11분 | 1,200원 | 25분 | 0원 | 1,200원 |

둘 다 20분 출발편을 타면 도착시각은 같아도 Q가 더 저렴하다.
중간에 P가 빠르고 저렴하다는 이유로 Q를 버리면 정답을 잃는다.
이런 작은 사례는 `정류장|도착이벤트|차량|운임이력`을 별도 노드 ID로 만들고,
대기·탑승 가능성과 추가 요금을 정적 연결로 명시하여 검증한다.
모든 후속 조건이 같아진 뒤에만 노드를 합쳐야 한다.
이 모듈이 문자열을 해석하거나 자동으로 시간표·운임 상태를 확장하지는 않는다.
실제 서비스 적용에는 완전한 상태 확장 또는 별도의 시간 의존 탐색 엔진과 데이터 구축이 필요하다.

## 검증과 다음 단계

저장소 루트에서 다음 명령으로 실행한다.

```powershell
python -m unittest discover -s algo/tests -p "test_pareto_search*.py" -v
```

검증은 탐색 구현과 독립적인 완전 열거 결과의 파레토 비용쌍과 일치하는지를 기준으로 한다.
A~D 꼴, 짧은 대기·긴 차내시간, 여러 환승 건너뛰기, 기존 경로 밖 연결, 비용 절충,
택시 2회 제외, 도달 불가, 순환과 동일 비용, 시간표·운임 이력을 구분한 작은 망을 다룬다.
고정 시드로 생성한 비순환 망 200개와 순환 망 40개에도 동일한 비교를 적용한다.
합격 기준은 비교한 모든 망의 파레토 비용쌍이 100% 일치하는 것이다.
시간표·운임 사례는 수작업으로 확장한 작은 망과 명시된 기대 결과를 비교한다.

일반화가 계산량 감소를 뜻하지는 않는다. 택시 연결 수와 파레토 라벨 수가 크게 늘 수 있다.
후속 연구에서는 이 정확한 기준 결과에 후보 제한을 적용하고, 누락된 비용쌍과 절약한 계산량을 비교한다.
서비스 연결, 실제 시간표·환승운임 계산, 후보 제한 정책은 별도 작업이다.

관련 연구인 [RAPTOR·McRAPTOR](https://www.microsoft.com/en-us/research/wp-content/uploads/2012/01/raptor_alenex.pdf)는
대중교통의 다기준 파레토 탐색을 다루고,
[ULTRA](https://arxiv.org/abs/1906.04832)는 대중교통과 비정기 교통수단 사이의 연결을 다룬다.
이 모듈은 두 알고리즘의 구현이 아니라, 택시 1회 제약을 상태에 추가한 정적 다중 라벨 기준 탐색이다.
